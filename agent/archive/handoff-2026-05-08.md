## Immediate Next Steps

1. **Define the canonical reading spine (first pass):**
   - Pick the smallest sequence of pages that gives a complete mental model without side quests.
   - Recommended candidate spine: `README.md` -> `artifacts/start-here.md` -> `artifacts/adversarial-committees.md` -> `artifacts/examples/full-pipeline-worked-example.md`.

2. **Create a breakout-box taxonomy and metadata schema (before UI build):**
   - Required box types:
     - `Research Note` (source grounding, citation context)
     - `Why This Matters` (decision relevance)
     - `Counterpoint` (adversarial framing)
     - `Method Detail` (procedural depth)
     - `Formalism` (palgebra/math bridge)
     - `Example Walkthrough` (concrete scenario)
   - Suggested front-matter fields for each box:
     - `id`, `type`, `title`, `source_refs`, `confidence`, `audience`, `estimated_read_time`, `prerequisites`, `related_boxes`.

3. **Adopt progressive disclosure UI rules (hard constraints):**
   - Default state: core narrative only; breakout boxes collapsed.
   - Max one expanded box at a time per viewport region.
   - Use soft visual hierarchy: muted borders/background tints, no heavy shadows, no animated attention traps.
   - Keep line length and spacing generous in core flow; depth should not visually compete.

4. **Implement relevance gating (to keep pages calm):**
   - Show only 1-3 "recommended" boxes contextually near each section.
   - Move additional boxes behind "More depth" affordance.
   - Add audience filter chips (`Practitioner`, `Theorist`, `Skeptic`, `Builder`) so users self-select complexity.

5. **Instrument learning usefulness (to optimize over time):**
   - Track expansions, dwell time in boxes, and return-to-core actions.
   - Use this to prune noisy boxes and identify missing explanatory layers.

## Watch-Outs for Successor

- **Do not conflate "more information" with "more visible information."** Depth must be opt-in.
- **Avoid semantic duplication:** if a breakout box repeats the main paragraph, it adds clutter without learning gain.
- **Do not over-style box variants:** too many colors/icons becomes dashboard noise.
- **Guardrail:** every box must answer one of:
  - "What evidence supports this?"
  - "What would challenge this?"
  - "How do I apply this?"
  If none apply, the box likely should not exist.
