## Mistakes and Lessons

- **SSR hydration bug**: Initial `useState` callbacks that read `localStorage` cause hydration mismatches in Next.js. Fixed by moving localStorage reads to `useEffect`. This is a known pattern but was present in the codebase before this session; fixing it during the layout restructure was the right time.
- **Confidence band [0, 3] bug**: The uncertainty band in `computeConfidenceMetrics` was clamped to [0, 3] instead of [1, 5] (the actual rubric scale). This meant high scores always produced inverted bands. Caught during test expansion and fixed. A test was added to prevent regression.
- **Metacognition regexes**: Vic's pattern had `/falsif/` which only matched a prefix; updated to `/falsif\w*/` to catch "falsifiable", "falsify", etc. Tammy's pattern had `/second-order/` which missed "second order" (no hyphen); updated to `/second[- ]order/`. These were pre-existing inaccuracies corrected during the metacognition deepening work.

## Watch-Outs for Successor

- **Don't assume metacognition = meta-d'**: The metacognition proxy is keyword counting, not psychophysical measurement. The deck review handoff (archived) flagged this as a speaker-note requirement. The demo now shows literal matched terms, which makes the keyword-counting nature more visible — but users may still over-interpret.
- **The `<details>` sections hide content**: If a user reports "the dashboard is missing," check whether they've expanded the right `<details>`. The tiered layout intentionally hides complexity by default.
- **Vote lines in prompts**: The `COMMITTEE_VOTE_FOOTER` instructs models to end with `Current vote: Aye/Nay/Undetermined`. If models don't comply, the fallback keyword inference still runs. But the declared-vote path is now the primary signal. If you change the prompt text, update the regex in `voteInference.ts` too.
- **15 new components were not reviewed line-by-line**: They were created in prior work. If you encounter rendering bugs, start with the new components — especially `RunLandscapeScatter`, `VoteTransitionFlowSvg`, and `CondorcetJuryExplorer` which involve SVG or canvas rendering.

## Theoretical/Conceptual Notes

- The Condorcet artifact expansion (§4) represents a significant repositioning: instead of just saying "we don't satisfy CJT," we now say "CJT is the wrong theorem, and here's what *does* theoretically ground our design." Hong-Page diversity is probably the closest analogue — incompatible heuristics over a shared problem landscape, with value coming from search strategy diversity rather than error independence.
- The distinction between "independence at generation" (deliberative dependence, our design) vs. "independence at evaluation" (fresh model instance, no shared context) is a clean structural insight. The committee applies each mechanism where it is productive. This is worth emphasizing in any technical presentation.
- The explicit vote protocol (Current vote: X on last line) makes the inferred-vote lens much more reliable. But it also changes the character dynamics slightly — characters are now prompted to commit positions explicitly rather than letting the vote emerge from text analysis alone. This is a trade-off worth monitoring: does explicit vote prompting make characters more rigid, or does it sharpen the deliberation?
